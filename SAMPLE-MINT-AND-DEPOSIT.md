# Experiment: mint A → wallet → B.deposit (receiveShielded) — the PASSING case

**Result: PASSED.** Contract B holds token A, because B *actively receives* it.
This is the receive that the two failing experiments lacked.

## Setup

Two `VaultToken` contracts (one ZK config, two roles) on one local v8 stack:

- contract **A** (token) : `0d10195a175dc2e5e2740d2db06c6e39dc084b3f2f364ce8da1daed2ce0dca27`
- contract **B** (vault) : `4495cf1a41bac161d50359308bff97f36f7da5d2bf9eab86c9129021649cb1bc`
- mint amount            : `1000000`

Compact 1.0 has no cross-contract calls, so A and B cannot act in one transaction.
The wallet bridges them across two txs:

1. `A.mint(recipient = wallet)` — token A lands in the wallet (mint to a coin pk).
2. `B.deposit(coin)` — `B.receiveShielded(coin)` takes it into B's custody.

## What happened

| tx | result |
|---|---|
| #1 deploy A | accepted |
| #2 deploy B | accepted |
| #3 mint (→ wallet) | accepted |
| #4 deposit (→ B) | **accepted** |

## Why it works (decoded deposit tx, `out/mad-4-deposit.decode.txt`)

```
entryPoint: deposit  (on contract B = 4495cf1a…)
guaranteed Zswap offer: inputs=1 outputs=1
  input[0]  Nullifier(c8c042cd…)                              # wallet spends its A-coin
  output[0] Commitment(bcbd05a7…) for: ContractAddress(4495cf1a… = B)
effects:
  claimed_shielded_receives: { bcbd05a7… }                    # B RECEIVES it  ← the difference
bytesWritten: 471                                             # B's _deposits counter ++
```

The output addressed to B (`bcbd05a7…`) is **matched** by B's
`claimed_shielded_receives` entry for the same commitment. With the receive
present, the contract-owned output is valid and the node accepts the tx.

## Contrast with the failures

| experiment | output `for: B` | `claimed_shielded_receives` | B called? | verdict |
|---|---|---|---|---|
| mint recipient = B | yes | `{}` empty | no | ❌ `186` |
| sendImmediateShielded → B | yes | `{}` empty | no | ❌ `186` |
| **B.deposit (this)** | yes | `{ bcbd05a7… }` | **yes** | ✅ accepted |

## Takeaway

A contract receives a shielded token only by **actively receiving** it
(`receiveShielded`) in the same transaction as the coin output. Since cross-contract
calls do not exist in Compact 1.0, getting a freshly minted token A into a *different*
contract B takes two txs: mint to the wallet, then deposit into B.
