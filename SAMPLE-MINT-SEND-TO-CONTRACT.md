# Experiment: mint A → self → sendImmediateShielded → recipient contract B

**Result: FAILED.** Forwarding a freshly-minted coin to a contract with
`sendImmediateShielded` is rejected just like minting straight to its address.
The send primitive is irrelevant; what matters is whether B receives.

## Setup

Two `MintSendToken` contracts (one ZK config, two roles) on one local v8 stack:

- contract **A** (mint+send) : `d0c05a3b6d29c30c335a62d87fac9ca876bf61182974705af7127a4381deaa58`
- contract **B** (recipient) : `06fe4ab77f47951c9c6c435e402ce568f9ef09c95fa091ba8f3b951d5c31abe4`
- mint amount               : `1000000`

`A.mintToContract(B, amount)` mints a coin to **A itself** (`kernel.self()`), then
forwards it to B with `sendImmediateShielded(ret, right(B), amount)`. B is
passive — it never calls `receiveShielded`.

## What happened

| tx | result |
|---|---|
| #1 deploy A | accepted |
| #2 deploy B | accepted |
| #3 mintToContract | **built + proven OK, then rejected at submission** |

Node rejection:

```
1010: Invalid Transaction: Custom error: 186
```

## Why (decoded mint tx, `out/msc-3-mintToContract.decode.txt`)

```
guaranteed_coins:
  transient: [ coin 2cae… Nullifier 02e9… for: ContractAddress(d0c05a3b… = A) ]   # self-mint: created + spent
  outputs:   [ coin d42a… for: ContractAddress(06fe4ab7… = B) ]                    # orphan: addressed to B
effects:
  shielded_mints:            { 30b4…: 1000000 }
  claimed_shielded_receives: { 2cae… }                  # A received its OWN coin
actions: [ mintToContract on A ]                        # only A; B never called
```

The mint-to-self half **works** — coin `2cae…` is received by A and spent (a valid
`transient`). The failure is the `sendImmediateShielded` output `d42a…` addressed
to B: B never receives it (`claimed_shielded_receives` has no entry for B, B is not
called). A contract-owned output with no matching receive is invalid.

## Takeaway

`sendImmediateShielded` does not deliver a coin to a *passive* contract any more
than the mint recipient does. The sender side is fine; the blocker is that B must
call `receiveShielded` (see `SAMPLE-MINT-AND-DEPOSIT.md` for the passing case).
