# Experiment: mint token A → recipient contract B

**Result: FAILED.** Minting a shielded token directly to a *contract address*
that does not participate in the transaction is **rejected by the node**.

## Setup

Two `ShieldedFungibleToken` contracts on one local v8 stack:

- contract **A** (token)     : `66889afbc856b8abb76540584a62c91b9dc14796f37d5a59da30408a1b880b3d`
- contract **B** (recipient) : `5eadf414af31a7d3f44c959a75feeb14741f729baad0336eb822b7571ac3b90e`
- mint amount                : `1000000`

`A.mint()` is called with the recipient `Either<ZswapCoinPublicKey,
ContractAddress>` set to the **right** (ContractAddress) variant = B's address,
instead of the usual left (wallet coin public key) variant.

## What happened

| tx | result |
|---|---|
| #1 deploy A | accepted |
| #2 deploy B | accepted |
| #3 mint A → B | **built + proven OK, then rejected at submission** |

Node rejection:

```
1010: Invalid Transaction: Custom error: 186
```

The transaction is well-formed and the ZK proof is valid. The failure is a
ledger **transaction-validity** rule, not a proving or build error.

## Why (decoded mint tx, `out/mtc-3-mint.decode.txt`)

```
guaranteed_coins:
  outputs: [ <shielded output Commitment(98b7…) for: ContractAddress(5eadf414… = B)> ]
  deltas:  [ ShieldedTokenType(9338…) -> -1000000 ]        # mint creates value
effects:
  shielded_mints:            { fd45…: 1000000 }            # the mint
  claimed_shielded_receives: { }                           # EMPTY
actions: [ mint on contract A ]                            # only A is called
```

The mint produces a coin **output owned by contract B** (`for:
ContractAddress(B)`), but **B never receives it**: `claimed_shielded_receives` is
empty and B is not called in the transaction. A coin owned by a contract must be
taken into custody by that contract — a `receiveShielded`, recorded as a claimed
shielded receive — in the *same* transaction. An orphaned contract-owned output
with no matching receive is invalid, so the ledger refuses the whole transaction.

Contrast: a normal `mint` to a *wallet* (recipient = left / coin public key)
produces an output `for: <coin public key>`, which is valid with no in-tx
receive. Users claim coins by scanning; contracts must actively receive.

## Takeaway

You cannot "push" a shielded token into a contract by minting to its address.
To get token A into contract B, B has to **receive** it:

1. one transaction where A sends and **B's circuit calls `receiveShielded`** (a
   cross-contract call), or
2. mint to a wallet first, then a transfer transaction in which B receives.

The bare `mintShieldedToken(..., recipient = ContractAddress(B))` with B passive
does not work.
